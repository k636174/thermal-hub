# Thermal Hub 初期リリース仕様書

## 1. 目的

Thermal Hub は、利用者がネットワーク上の ESC/POS 対応サーマルプリンターを管理し、DB に保存した印字内容を必要な時に編集・送信できる Web ツールである。

## 2. 対象範囲

- Web 画面でのログイン／ログアウト
- CLI によるアカウント登録
- ログインアカウントごとの複数プリンター登録・編集・削除
- ログインアカウントごとの印字内容の登録・編集・削除
- 保存済み印字内容を、選択した登録済みプリンターへ TCP 送信
- 印字結果（成功／失敗、日時、メッセージ）の保存

アカウントの Web 登録、画像印刷、印刷予約、プリンター状態監視、複雑な ESC/POS レイアウト編集は初期リリースの対象外とする。

## 3. 機能要件

### FR-01 認証

1. メールアドレスとパスワードでログインできる。
2. パスワードは安全なハッシュ形式で保存し、平文保存しない。
3. ログアウト時に認証セッションを破棄する。
4. ログイン画面以外の業務画面は未認証アクセスを拒否する。

### FR-02 CLI アカウント登録

1. `bin/cake user create <email> <name>` で登録を開始できる。
2. パスワードは対話入力し、8文字以上を要求する。
3. メールアドレスは一意とする。
4. 対話入力中のパスワードはコンソール画面へ表示しない。
5. CakePHP 5.4が提供しないAPIへ依存せず、WindowsとUnix系端末で非表示入力を行う。
6. Windowsでは最初の1文字で確定せず、Enterキーが押されるまで入力した全文をパスワードとして扱う。

### FR-02-1 CLI パスワードリセット

1. `bin/cake user reset-password <email>` で指定アカウントのパスワードを変更できる。
2. 新しいパスワードと確認値は対話形式かつ画面へ表示せずに入力する。
3. 新しいパスワードは8文字以上とし、確認値との一致を要求する。
4. 指定したメールアドレスのアカウントが存在しない場合は変更せずエラー終了する。
5. 成功時は新しいパスワードを安全なハッシュ形式で保存する。
6. Windowsでは最初の1文字で確定せず、Enterキーが押されるまで入力した全文を新しいパスワードとして扱う。

### FR-03 プリンター管理

1. 名称、ホスト名またはIPアドレス、TCPポート、文字エンコーディング、接続タイムアウトを登録できる。
2. 1アカウントに複数台登録できる。
3. CRUDは所有アカウントのデータだけを対象とする。
4. ポートは1～65535、タイムアウトは1～30秒とする。

### FR-04 印字データ管理

1. タイトルと本文を保存できる。
2. CRUDは所有アカウントのデータだけを対象とする。
3. 本文は必須で最大100,000文字とする。

### FR-05 印字

1. 保存済み印字データと登録済みプリンターを選択して即時印字できる。
2. UTF-8本文をプリンター設定のエンコーディングへ変換し、初期化、改行、紙送り、カット命令を付加してTCP送信する。
3. 接続または送信失敗は画面に表示する。
4. 成否、送信先、印字データ、実行日時、結果メッセージを履歴に保存する。
5. 他アカウントのプリンターまたは印字データは指定できない。
6. 印字時に用紙長を「指定なし」「システム手帳 ナロー（170mm）」「M5／マイクロ5（105mm）」から選択できる。
7. 「指定なし」は従来どおり本文の後に3行紙送りしてカットする。固定長では、既定行間30ドット（203dpi）を基準に本文の改行数から印字長を算出し、選択した長さまで紙送りしてカットする。本文が指定長を超える場合も本文を欠落させず、3行紙送りしてカットする。
8. 不正な用紙長が送信された場合は印字せず、入力エラーとして扱う。
9. CP932またはShift_JISで印字する場合は、ESC/POSの漢字コード体系をShift_JISに設定して漢字モードで本文を送信する。UTF-8の場合は漢字モード命令を付加しない。

## 4. データモデル

- `users`: id, email, name, password, created, modified
- `printers`: id, user_id, name, host, port, encoding, timeout, created, modified
- `print_jobs`: id, user_id, title, body, created, modified
- `print_logs`: id, user_id, printer_id, print_job_id, status, message, printed_at, created

全ての外部キーにインデックスを設ける。ユーザー削除時は関連データを削除する。

## 5. 非機能要件

- CakePHP 5.4 / 64bit版PHP 8.2以上で動作する（Migrationsの14桁バージョンを扱うため）。
- DB変更はMigrationsで管理する。
- CSRF保護を有効にする。
- TCP接続は設定された短いタイムアウトで終了する。
- 所有者チェックをサーバー側で必ず実施する。

## 6. 受入条件

- CLIで作ったアカウントがログイン／ログアウトできる。
- 同一ユーザーが複数プリンターと複数印字データをCRUDできる。
- 別ユーザーのデータをURLやPOST値の改変で参照・更新・印字できない。
- 到達可能なTCPサーバーへESC/POSバイト列を送信でき、成功履歴が残る。
- 到達不能な送信先では失敗履歴が残り、エラーが表示される。
- 印字画面で3種類の用紙長を選択でき、170mmおよび105mmでは本文の行数に応じたESC/POS紙送り命令が付加される。
- CP932／Shift_JIS設定のプリンターでは、日本語本文がShift_JISの漢字モード命令とともに送信される。

## 7. 仕様変更手順

機能変更は、先に本書または `docs/specs/` 配下の差分仕様を更新し、受入条件を明記してから実装・テストを変更する。
