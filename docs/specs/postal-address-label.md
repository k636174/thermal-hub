# 郵便宛先ラベル印字 設計書

## 1. 目的

Thermal Hub に、郵便物へ貼付する宛先ラベルを作成・プレビュー・印字する機能を追加する。サーマルプリンターの印字可能幅が狭いため、画面上では通常の横書きで入力し、印字時にラベル全体を時計回りに90度回転して用紙へ配置する。

本書は設計までを対象とし、実装、DB migration、テスト追加は行わない。

## 2. 前提と設計方針

- 対象は、現在サポートしている203dpiのネットワーク接続ESC/POSプリンターとする。
- 初期値は印字可能幅72mm（576dot）、ラベル長100mm（799dot）とする。ただし機種・用紙に合わせてプリンターごとに変更できるようにする。
- 「ラベル幅」は回転前の横方向、「ラベル長」は回転前の縦方向を表す。90度回転後はラベル幅が用紙送り方向、ラベル長がプリンターのドット幅方向になる。
- ESC/POSの文字回転命令は日本語フォント、位置指定、機種互換性に差があるため使わない。UTF-8の入力からモノクロ画像を生成し、画像全体を時計回りに90度回転した後、GS v 0ラスター形式で送信する。
- プレビューと印字は同じレイアウト処理の結果を使用し、見た目の差を抑える。
- 初期リリースでは宛先だけを扱う。差出人、郵便番号枠、QRコード、住所録、CSV一括取込、複数ラベルの連続印刷は対象外とする。

## 3. 用語と寸法

| 用語 | 意味 | 初期値 |
|---|---|---:|
| 印字可能幅 | プリンターが1行に印字できる幅 | 576dot / 約72mm |
| ラベル幅 | 物理的な用紙幅。回転前レイアウトの高さ、回転後の横幅 | 72mm |
| ラベル長 | 用紙送り方向の長さ。回転前レイアウトの横幅、回転後の高さ | 100mm |
| 解像度 | mmとdotの換算に使用 | 203dpi |
| 安全余白 | 文字切れを防ぐ上下左右の余白 | 各3mm |

換算は `dots = round(mm * dpi / 25.4)` とする。ラベル幅から求めた回転後画像の横dot数がプリンターの印字可能幅dot数を超える設定は保存および印字を拒否する。

## 4. 機能要件

### FR-AL-01 宛先ラベル管理

1. ログインユーザーは宛先ラベルを追加、一覧表示、編集、削除できる。
2. ラベルには管理用タイトル、郵便番号、住所1、住所2、宛名、敬称を保存できる。
3. 管理用タイトル、住所1、宛名は必須とする。住所2は建物名・部屋番号等に使用する。
4. 郵便番号は未入力を許可する。入力時は7桁の数字を受け付け、表示時は `123-4567` に正規化する。
5. 敬称は `様`、`御中`、`行`、`なし` から選択する。初期値は `様` とする。
6. CRUDはログインユーザーが所有するデータだけを対象とする。

### FR-AL-02 レイアウトとプレビュー

1. 編集画面に横書き状態のプレビューを表示する。
2. プレビューには郵便番号、住所1、住所2、宛名と敬称を表示する。
3. 郵便番号は上段、住所は中段、宛名は下段に配置し、宛名を最も大きい文字で表示する。
4. 改行はフィールドの境界または文字幅に基づきサーバー側で決定し、入力値に任意の制御命令を含めない。
5. 文字が領域に収まらない場合は、設定した最小フォントサイズまで段階的に縮小する。それでも収まらない場合は省略せず入力エラーとし、対象フィールドを画面に示す。
6. プレビュー画像の取得は認証必須とし、所有者検証を行う。未保存の入力内容をプレビューする場合もCSRF保護されたPOSTを使用する。

### FR-AL-03 90度回転印字

1. ユーザーは保存済みラベルと所有する登録済みプリンターを選び、1枚を即時印字できる。
2. サーバーは横書きのモノクロ画像を生成し、時計回りに90度回転する。
3. 回転後画像をESC/POSラスター形式へ変換し、初期化、行間0、画像、必要最小限の紙送り、全カット命令の順にTCP送信する。
4. 画像は1bit白黒とし、既定では誤差拡散を使わず閾値処理する。文字の輪郭を優先し、写真向け処理は行わない。
5. プリンターの画像印字能力が無効、または設定寸法が印字可能幅を超える場合は送信しない。
6. 成否、プリンター、ラベル、実行日時、結果メッセージを印字履歴へ保存する。
7. 他ユーザーのラベルまたはプリンターはURL・POST値を変更しても参照・印字できない。
8. 送信した画像バイト列および宛先の本文はログメッセージへ保存しない。

### FR-AL-04 プリンター設定

1. プリンターに解像度、印字可能幅dot、ラベル幅mm、ラベル長mm、画像印字の有効・無効を設定できる。
2. 解像度は初期リリースでは203dpiのみ選択可能とする。将来の300dpi対応を妨げないデータ型とする。
3. 印字可能幅は128～832dot、ラベル幅・長さは20.0～300.0mmの範囲とする。
4. 保存時に回転後画像が印字可能幅へ収まることを検証する。

## 5. 画面設計

### 5.1 ナビゲーション

既存の「印字データ」と分けて「宛先ラベル」を追加する。自由本文の印字フローは変更しない。

### 5.2 宛先ラベル一覧 `/address-labels`

- 表示項目: 管理用タイトル、宛名、郵便番号、更新日時
- 操作: 追加、編集、削除
- 印字欄: プリンター選択、印字ボタン
- 印字前に宛名と選択プリンターを確認するダイアログを表示する。

### 5.3 追加・編集 `/address-labels/add`, `/address-labels/edit/{id}`

- 入力: 管理用タイトル、郵便番号、住所1、住所2、宛名、敬称
- 右側または入力欄の下に横書きプレビューを表示する。
- プレビューは入力停止後に更新するが、JavaScriptが無効でも「プレビュー更新」ボタンで利用できる。
- 画面上に「印字時は時計回りに90度回転します」と表示し、回転方向を小さな図で示す。

## 6. レイアウト仕様

### 6.1 回転前キャンバス

回転前キャンバスは横長の `ラベル長 × ラベル幅` とし、白背景に黒文字で描画する。各辺3mmを安全余白とする。

縦方向の領域配分は次を既定とする。

| 領域 | 高さの目安 | 配置 | 基準フォント |
|---|---:|---|---:|
| 郵便番号 | 18% | 左上 | 16pt相当 |
| 住所 | 42% | 左揃え・最大3行 | 18pt相当 |
| 宛名 | 40% | 中央寄せ | 28pt相当 |

プリンター上端の非印字領域を避けるため、全ての内容を安全余白からさらに11mm下げ、その上で郵便番号を8mm下げる。住所の描画開始位置はラベル幅の27%、宛名は60%を基準としてさらに3mm上へ寄せ、住所と宛名の間隔を詰めつつ重ならない配置とする。

フォントはリポジトリに同梱する日本語対応フォントを明示指定し、OSのインストール状態に依存させない。フォントのライセンス表記も同梱する。

### 6.2 収まり判定

1. 各フィールドをUnicode文字列として正規化する。
2. 禁止する制御文字を除外し、改行・タブは半角スペースへ正規化する。
3. 実際のフォントメトリクスで文字列幅を測定して折り返す。
4. 基準サイズから1ptずつ縮小し、領域内へ収まるか判定する。
5. 最小サイズ（住所12pt相当、宛名18pt相当）でも収まらなければエラーにする。

### 6.3 回転と送信

横書きキャンバスを時計回りに90度回転する。回転後の画像サイズは概ね `ラベル幅dot × ラベル長dot` となる。回転後の画像は移動せず、ESC/POSでは回転後の横方向をプリンターの印字可能幅へ中央寄せして送信する。

画像コマンドは `GS v 0` を使用する。1行を8dot単位のバイト列へ変換し、余った右端bitは白で埋める。ペイロード上限を設け、生成画像が上限を超える場合は送信前にエラーとする。

## 7. データモデル

### 7.1 新規 `address_labels`

| カラム | 型 | 制約 |
|---|---|---|
| id | integer | PK |
| user_id | integer | FK users, NOT NULL, index |
| title | string(200) | NOT NULL |
| postal_code | string(7) | NULL |
| address_line1 | string(255) | NOT NULL |
| address_line2 | string(255) | NULL |
| recipient_name | string(200) | NOT NULL |
| honorific | string(20) | NOT NULL, default `様` |
| created | datetime | NOT NULL |
| modified | datetime | NOT NULL |

ユーザー削除時はCASCADEで削除する。Entityのmass assignmentでは `user_id` を許可せず、Controllerで認証ユーザーIDを設定する。

### 7.2 `printers` 追加カラム

| カラム | 型 | 初期値 |
|---|---|---:|
| dpi | integer | 203 |
| printable_width_dots | integer | 576 |
| label_width_mm | decimal(6,1) | 72.0 |
| label_length_mm | decimal(6,1) | 100.0 |
| raster_enabled | boolean | true |

### 7.3 `print_logs` 変更

- `print_job_id` をNULL許可に変更する。
- `address_label_id` をNULL許可の外部キーとして追加する。
- `document_type` (`text` / `address_label`) を追加する。
- `document_type` に対応する参照IDが片方だけ設定されることをアプリケーションルールで保証する。
- 履歴保持のため、ラベル削除時の `address_label_id` は `SET NULL` とする。宛先本文のスナップショットは保存しない。

## 8. コンポーネント設計

| コンポーネント | 責務 |
|---|---|
| `AddressLabelsController` | 所有者スコープ付きCRUD、プレビュー、印字要求の調整 |
| `AddressLabelsTable` | 入力validation、所有者関連、敬称ルール |
| `AddressLabelLayoutService` | 正規化、折返し、フォントサイズ決定、横書きキャンバス描画 |
| `RasterImageService` | 90度回転、1bit化、GS v 0データ生成 |
| `EscPosPrinterService` | TCP接続、完全送信、共通ESC/POS命令の付与 |
| `AddressLabelPrintService` | 設定検証、上記サービスの連携、印字結果の返却 |

Controllerから画像処理やTCP送信を直接行わない。レイアウト結果は、プレビュー用PNGと印字用1bitビットマップの共通中間表現から生成する。

想定フロー:

```text
入力/保存データ
  -> 所有者・validation
  -> 横書きレイアウト生成
  -> 収まり判定
  -> 時計回り90度回転
  -> [プレビューPNG] または [1bit化 -> GS v 0 -> TCP送信]
  -> 結果履歴
```

## 9. API・ルーティング

CakePHPのDashedRouteに従い、次のactionを追加する。

- `GET /address-labels` 一覧
- `GET|POST /address-labels/add` 追加
- `GET|PATCH|POST|PUT /address-labels/edit/{id}` 編集
- `POST|DELETE /address-labels/delete/{id}` 削除
- `POST /address-labels/preview` 未保存入力のPNGプレビュー
- `POST /address-labels/print-now/{id}` 保存済みラベルの印字

プレビュー応答は `image/png`、`Cache-Control: no-store` とする。

## 10. セキュリティ・運用

- 全ての検索・更新・印字で `user_id` を条件に含める。
- ラベルIDとプリンターIDはサーバー側で同一ログインユーザーの所有物か検証する。
- 全変更・プレビュー・印字はCSRF保護対象とする。
- フォントパス、任意画像、任意ESC/POS命令をユーザー入力として受け取らない。
- TCP送信先は登録済みプリンターに限定する。既存の登録時検証に加え、可能であればループバック、リンクローカル、クラウドメタデータ等への接続禁止を別途検討する。
- エラーログにはラベル本文、生成PNG、ESC/POSペイロードを出力しない。
- PHPの画像描画拡張（GDまたはImagick）と同梱フォントをデプロイ要件へ追加する。採用ライブラリは実装開始時に実行環境で確認して決定する。

## 11. エラー処理

- 入力不正: フィールド単位で画面表示し、保存・印字しない。
- レイアウト超過: 収まらないフィールド名を表示し、文字を欠落させない。
- 設定寸法超過: 必要dot数とプリンターの印字可能幅を示して送信しない。
- 画像生成失敗: 一般化したメッセージを画面表示し、詳細は個人情報を含めずサーバーログへ記録する。
- 接続・送信失敗: 既存印字と同様に失敗履歴を保存する。

## 12. テスト方針

### Unit

- mmからdotへの換算と境界値
- 郵便番号の正規化とvalidation
- 日本語・英数字・異体字を含む文字幅計測と折返し
- 最小フォントまでの縮小、および収まらない場合のエラー
- 指定画像の時計回り90度回転（四隅のテストパターンで向きを検証）
- 1bit化とGS v 0の幅・高さ・bit順
- 印字可能幅超過とペイロード上限

### Integration / Controller

- 所有ユーザーだけがCRUD、プレビュー、印字できること
- 他ユーザーのラベル・プリンター指定が404または拒否になること
- CSRF、HTTP method制限、validationエラー
- 成功・失敗時に正しい `document_type` の履歴が残ること

### Golden image / 実機

- 固定入力から生成した回転前PNGと回転後1bit画像を基準画像と比較する。
- 実機で、回転方向、上下左右の欠け、ラベル長、カット位置、日本語の可読性を確認する。
- 少なくとも短い住所、長い住所、住所2なし、郵便番号なし、長い法人名を確認する。

## 13. 受入条件

1. ユーザーが郵便番号、住所、宛名、敬称を保存し、横書きプレビューを確認できる。
2. 印字物ではプレビュー内容が時計回りに90度回転され、指定したラベル領域内に欠落なく収まる。
3. 日本語住所と宛名が画像として判読可能に印字され、プリンター搭載フォントに依存しない。
4. 寸法または文字量が許容範囲を超える場合、印字せず明確な入力エラーとなる。
5. 他ユーザーの宛先情報およびプリンターを参照・編集・印字できない。
6. 印字成功・失敗の履歴が保存され、ログに宛先本文や画像データが残らない。
7. 既存の自由本文印字と固定長印字の動作が変わらない。

## 14. 実装前に実機で確定する事項

設計の既定値は上記で定義するが、実装着手前に次を実機で確認する。

- プリンター型番とGS v 0対応状況
- 用紙幅、実際の印字可能幅dot、カッターから印字位置までの余白
- 使用するラベルの完成寸法と、ラベルを貼る向き
- 90度回転が時計回りで正しいこと（逆向きなら設定値として切り替える）
- GD/Imagickの利用可否と、日本語フォント（Noto Sans JP）のライセンス
